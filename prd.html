0假设与前提

信息不足处先固化假设，避免方案空转；若假设被推翻，只需替换对应模块，不影响整体架构。

编号假设若不成立的影响
A1 对比对象是两个本地目录树（可含 .git，但不依赖同一仓库）。 若需远程仓库拉取，增加网络/认证模块（P1）。
A2 主要服务源代码与配置文本，二进制只做「有无差异」识别，不做语义 diff。 图片/资源对比可作为 P2 插件。
A3 单机本地运行，数据不出本机；目标用户可接受 CLI 与桌面 GUI 双形态。 若必须纯 Web，需服务端扫描与权限模型，体积与复杂度上升。
A4 典型工程规模：≤ 50k 文件 / ≤ 2 GB 文本；更大工程可按需加载。 超大规模需索引缓存与后台任务队列（P2）。
A5 UI 采用白底 Harness 风格：浅灰分区、蓝色强调、圆角卡片、高信息密度。 视觉系统独立可换肤，不阻塞功能。

1产品定位

把「两个独立工程」的结构级与内容级差异，变成一次可扫描、可阅读、可导出的工程对比任务。

一句话价值主张

一次选择两个工程，自动生成可读、可筛、可导出的全量代码差异报告与逐文件 diff 视图。

本地运行 · 轻量安装 · 不依赖 Git 同源历史

目标用户

  • 需要做 版本基线对齐 / 迁移核对 的研发工程师
  • 交付前做 两套副本一致性检查 的实施/运维
  • 做 开源分叉、客户定制版 差异审计的架构师
  • 希望用 CLI 批量出报告的 CI/脚本作者

核心使用场景

迁移核对

老工程 → 新工程重构后，确认哪些文件被改、哪些被删、哪些新增，输出 Markdown 报告给评审。

定制版审计

官方版 vs 客户定制版，快速定位改动文件，过滤 node_modules / build，生成 HTML 报告。

交付一致性

现场部署目录与签核目录对比，识别缺文件与内容漂移，导出 CSV 作为验收附件。

产品边界：不做 Git 托管、不做在线协作、不做代码托管平台同步。它解决的是「两个独立工程如何高效对齐认知」，而不是「版本管理」。

3核心功能设计

围绕「选对工程 → 匹配文件 → 高效 diff → 导出结果」四步展开，每一步都有明确的规则与默认值。

3.1 选择两个工程

  • 支持文件夹选择器、拖拽目录、粘贴路径；可选用 Git 工作区根目录（含 .git）。
  • 工程 A（左）/ 工程 B（右）语义固定：A 为基准，B 为对照；「新增」= 仅在 B，「删除」= 仅在 A。
  • 记录最近 10 组工程对（本地配置，不上传）。
  • 交换 A/B 一键按钮；对比前校验：路径存在、可读、非同一路径。

3.2 文件扫描与映射

映射策略（默认）

  1. 以相对工程根的 POSIX 路径作为键精确匹配。
  2. 大小 + 快速哈希预筛：相同 size/hash → 一致，跳过内容 diff。
  3. 其余文件进入分类与按需内容 diff。
  4. P1 开启重命名：未匹配且哈希相同 → Rename；相似度 > 阈值 → Probable Rename。

状态枚举

Same Modified Deleted Added Binary Renamed Ignored Large

UI 图标与颜色全局一致：绿=同/新增可选、琥珀=改、红=删、蓝=新增、灰=二进制/忽略。

3.4 逐文件 Diff

视图模式

  • 并排（Side-by-Side）：适合窄改动；支持同步滚动、对齐空白。
  • 统一（Unified）：适合生成 patch 阅读与复制。
  • 行内高亮：字符级/词级高亮修改片段（在行级 diff 基础上叠加）。
  • 折叠未变更上下文（默认 ±3 行，可展开）。
  • 支持「只看变更行」、复制行、复制 hunk、跳转下一个变更（N/P 或工具栏）。

3.5 整体结果与统计

摘要指标

  • 新增文件数 / 删除文件数 / 修改文件数 / 一致文件数
  • 二进制差异数 / 重命名对数
  • 总变更行数（+add / −del）
  • 变更文件按目录聚合 Top N
  • 扫描耗时、跳过忽略数、大文件数

过滤与搜索

  • 按状态多选过滤（仅改 / 仅增删…）
  • 路径/文件名模糊搜索
  • 变更行数范围过滤（> N 行优先看）
  • 正则内容搜索（P1，结果跳转到文件）

格式内容适用优先级

4非功能需求

轻量、跨平台、本地隐私、大工程可用，是选择技术方案的硬约束。

体积与安装

  • 安装包目标：≤ 30 MB（理想 10–20 MB）
  • 免管理员权限安装（Windows NSIS / macOS DMG / Linux AppImage）
  • 不捆绑浏览器内核（避免 Electron 100MB+）

性能目标

  • 1 万文件扫描 + 哈希预筛：< 3 s（SSD，缓存冷）
  • 5 万文件工程：< 12 s 完成摘要；UI 可中途看进度
  • 单文件 diff 首屏：< 200 ms（普通源文件）
  • 大文件：虚拟滚动，DOM 不随行数线性膨胀

平台与兼容

  • Windows 10/11、macOS 12+、主流 Linux x64
  • 深浅色：默认浅色；P2 跟随系统
  • 高 DPI / 缩放 100–200%

隐私与安全

  • 100% 本地处理，不上传代码
  • 遥测默认关闭；若开启仅匿名崩溃栈
  • 导出报告路径由用户显式选择

稳定性与可维护性

维度要求
大文件阈值跳过 + 强制打开警告 + 虚拟滚动
编码UTF-8 优先；BOM 检测；失败降级字节 diff
换行比较时可归一；导出可选保留
二进制永不按文本渲染；UI 显示 size/hash
权限单文件失败不拖垮全局；错误列表可导出
扩展核心库与 UI 解耦；导出器、忽略器可插拔

5技术方案

推荐 Tauri 2 + Rust 核心 + 轻量前端；CLI 与 GUI 共享同一 Rust core，避免两套 diff 实现。

5.1 技术选型

层选型备选理由
桌面壳 Tauri 2 Wails 系统 WebView、安装包小、Rust 同源、跨平台成熟
核心 Rust Go 并行、内存安全、diff/ignore 生态好、静态链接体积可控
前端 Svelte 5 或 React 18 + Vite Vue 开发效率高；Svelte 产物更小，二者均可。推荐 Svelte 控体积
Diff 渲染 自研虚拟列表 Diff 视图 CodeMirror 6 / Monaco Monaco 过重；CodeMirror 可做编辑器，但纯 diff 展示自研更轻、更可控
CLI clap + 同一 core crate 独立 CLI 语言 复用扫描/哈希/diff/导出，行为一致
为什么不默认 Electron：安装包通常 80–150 MB，内存占用高，与「体积小、本地轻量」目标冲突。Tauri 使用系统 WebView，安装包常可压到 10–25 MB 量级。

5.2 关键实现思路

文件遍历与忽略

  • 使用 ignore crate（含 gitignore 语义）+ 自定义 globset 叠加。
  • walkdir / ignore::WalkParallel 并行遍历 A/B。
  • 符号链接默认不跟随；检测到循环则跳过并计入警告。

哈希预筛

  • 第一键：相对路径；第二键：size。
  • size 相同才计算 blake3（可只读首尾 64KB 做 fast-hash，冲突再全量）。
  • hash 相同 → Same（或 Rename 候选）。

Diff 算法

  • 行级：优先 imara-diff（Myers/Patience，适合大文件）或 similar。
  • 词级/字符级高亮：对「改」行再跑短串 LCS。
  • 输出内部 hunk 模型，再序列化为 unified diff / JSON / HTML。

重命名检测（P1）

  • 集合：Deleted × Added。
  • 哈希全等 → 确定 Rename。
  • 否则相似度（如 token 相同率）≥ 0.6 → Probable Rename；在 UI 可折叠为一对。

二进制检测

  • 魔数（PNG/PDF/ZIP/ELF…）或前 8KB 含 NUL / 高比例不可打印字节 → Binary。
  • Binary 只比较 size + hash，UI 显示「二进制差异」。

5.7 性能要点

扫描

6.3 组件规范

组件规范
工程选择器浅灰底输入条 + 浏览按钮；路径 monospace；错误态红描边 + 说明文案

加载顶部细进度条 + 扫描中数字跳动；可取消
错误卡片内联错误，不打断布局；提供「重试 / 更换路径」
Toast成功导出显示 3s；可关闭

6.5 关键页面说明

空状态 / 欢迎

大面积留白 + 标题「对比两个工程」+ 双路径槽位 +「开始对比」；下方三枚场景快捷入口（迁移 / 审计 / 验收）。

对比结果

三栏布局（树 / Diff / 统计）；顶部保留 A/B 路径与交换按钮；底部状态栏常驻扫描摘要。

导出对话框

多选格式、是否包含 hunks、输出目录、文件名模板；预估报告大小；成功后 Toast + 打开文件夹。

设置

忽略预设开关、行尾策略、编码策略、大文件阈值、主题（浅色默认）、最近工程清除。

7实施计划

MVP 锁定 P0；两周为一迭代，6–8 周可内部试用，10–12 周可对外 1.0。

7.1 MVP 范围（必须有）

  • 选择两个目录，忽略规则（预设 + 基本自定义）
  • 文件映射与状态分类（含二进制识别）
  • 并排 + 统一 diff，行级高亮
  • 工程统计摘要与简单过滤
  • 导出 patch + JSON
  • Windows 优先打包，macOS/Linux 紧随

7.2 迭代路线图

  • M0 · 立项与骨架（1 周）
    仓库结构、core 空接口、Tauri 壳、CI 构建、DESIGN 定稿
  • M1 · 扫描与映射（2 周）
    遍历、忽略、哈希预筛、状态分类、JSON 报告、CLI compare 雏形
  • M2 · Diff 引擎与视图（2 周）
    imara/similar 集成、hunk 模型、并排/统一视图、虚拟列表
  • M3 · 统计 / 过滤 / patch 导出（1–2 周）
    摘要面板、过滤搜索、unified diff 导出、错误与空态打磨
  • M4 · 报告与体验（2 周）
    HTML/MD/CSV、重命名检测、编码/行尾策略、性能压测
  • M5 · 1.0 打磨与分发（2 周）
    三端打包、快捷键、文档、示例工程、回归用例、发布

7.3 风险与规避

风险影响规避
超大工程卡顿 体验差、内存暴涨 并行扫描、哈希预筛、大文件跳过、虚拟滚动、分页加载 hunks
diff 算法在极端文件退化 耗时过长 时间/规模上限；超限降级为「仅统计」；imara patience 模式
Windows 路径/编码坑 错比、乱码 全程 UTF-8 内部表示；encoding_rs；集成中文路径用例
Tauri WebView 差异 UI 不一致 控制 CSS 兼容面；以 Windows WebView2 / macOS WKWebView 实测为准
范围蔓延（语义 diff / 在线协作） 延误 1.0 严格 P0 边界；P2 插件化，不进主路径
